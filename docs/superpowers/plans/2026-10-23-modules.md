# Modules Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship jumpgate's first modules, all built on one `Module` definition: the message board, EL and CL bootnodes, a health watch, private send on Ethereum, and Checkpointz. Each one can be turned on from the app and the TUI, and each shows its status.

**Architecture:** A `Module` is catalog data (`internal/catalog/modules.go`) with one of three **placements**, and the placement decides where it is recorded and what renders it:
- `node`: flags and namespaces on a node's execution client, recorded in `WireConfig.Modules` (msgboard).
- `box`: its own systemd unit on a box, recorded in `config.Target.Modules` (bootnodes, health watch, Checkpointz).
- `gateway`: method routing on an eRPC gateway, recorded in `GatewayConfig.Modules` (private send).

Every placement shares the same `Applies`, validation, the same `PUT …/modules/{module}` route shape, the setup run and SSE stream, `monitor.ModuleStatus`, and one generic card in the UI and one in the TUI. Gateway exposure is one derived pair of upstream fields, `IgnoreMethods` and `AllowMethods`, rendered into eRPC. The relay gets one rule on top: module write methods need an explicit key grant.

**Tech Stack:** Go 1.26.0 (module `github.com/valve-tech/jumpgate`, CGO off), systemd, eRPC (valve-ws branch) YAML, Caddy, React and Vitest (`cmd/jumpgate/web`), Bubble Tea v2 (`internal/tui`), the Docker e2e harnesses (`scripts/e2e-agent.sh`, `JUMPGATE_DOCKER_LIVE=1`).

**Spec:** `docs/superpowers/specs/2026-10-22-msgboard-module-design.md` (the Module definition, and msgboard D1–D11). Research: `.claude/research/modules-now.md` (the per-module verdicts), `.claude/research/msgboard.md`, `.claude/research/pulsechain-builder.md`. Docs format: `docs/superpowers/specs/2026-10-17-docs-system-design.md` §1 and §3.

**Extends the spec:** the spec's D1 defines only node add-ons and leaves "a standalone box" to its own spec. This plan settles that here (D-P below), with one `Module` type, so the box and gateway modules follow the same rules the spec sets for msgboard.

## Decisions this plan adds to the spec

- **D-P. Placement.** `Module.Placement` is `node`, `box` or `gateway`. Every field the spec defines keeps its meaning. Fields that only one placement uses are zero for the others, and an init-time check enforces that (Task 2).
  - `Namespaces`, `Flags` and `Methods` are for `node` only.
  - `Unit` is for `box` only.
  - `Routes` is for `gateway` only.
- **D-B. Box modules.**
  - **Unit name.** Each runs as its own unit, `jumpgate-mod-<instance>.service`. The instance is `<id>-<chainId>`, or `<id>` for a chain-agnostic module.
  - **Account and data.** It runs under the `CurrentNames` account (`jumpgate-node`), with data in `/var/lib/jumpgate-node/modules/<instance>/`.
  - **Unit template.** It uses the same hardened template as node units.
  - **Sidecar.** Setup writes `module.json` (the `BoxModule` record) into that directory. A gate or an SSH probe can then list a box's modules without the controller's config.
  - **Plan.** A box module is installed by `setup.PlanBoxModule`, a short plan beside `setup.Plan`, as `PlanGateway` already is. It does not need a node on the box.
- **D-G. Gateway modules.**
  - **What is stored.** The gateway records only the module id. The routes are derived at render time, in the same place `Endpoint` is derived for managed upstreams.
  - **Which chains.** A gateway module acts on the chains it `Applies` to. A gateway that also serves other chains renders them unchanged.
- **D-S. Status for box modules** uses a new routine intent, `modules.read`. Like `agent.info`, it needs no `node.json`, so a bootnode-only box reports status through its gate. For an SSH-only target, the server runs the same probe (`monitor.ProbeBoxModules`) over the shell executor.
- **D-H. Hoodi** (560048) is added as a full network in Task 1:
  - clients: reth and geth, with lighthouse;
  - Valve publishes no snapshot for it, so `SnapshotSizeTB` is 0;
  - preflight skips the disk-size floor and says so, instead of inventing a number.

## Global Constraints

- **Toolchain.** Go 1.26.0, module path `github.com/valve-tech/jumpgate`, `CGO_ENABLED=0`. Add no new Go modules.
- **"Gate".** User-facing text says **gate** for the per-box program. Write "the box's gate" wherever "gateway" is nearby. Go names, `jumpgate-agent.service`, `jumpgate agent …` and intent kinds are unchanged.
- **Never `all`.** `--http.api all` and `--ws.api all` are never rendered, and neither is `none`. `TestNoAPIListIsAll` is merge-blocking.
- **Units stay identical.** With no modules, every rendered node unit, gateway config and Caddyfile is byte-identical to its output at `1ef27cf`. Goldens are taken at that commit (Task 3 Step 1) and are never regenerated by a later task.
- **Applies.** `Module.Applies(chainID int, client string) (ok bool, reason string)`.
  - `ok == false` with `reason == ""` hides the toggle.
  - A non-empty reason disables it and shows the reason verbatim.
  - The UI and the TUI never re-derive `Applies`. They read it from `/api/catalog`.
- **Exact copy.** Each task gives its own exact copy where it adds a string. The rest come from the spec:
  - D4 restart line: `This restarts reth on <box>. The beacon keeps running.`
  - D10 reasons, for example `The message board needs reth (valve fork). This node runs go-pulse.`
  - D7 refusal: `msgboard_addMessage needs to be on this key's method allow list`
  - D7 stream refusal: `subscriptions other than eth_subscribe are not supported on this endpoint; poll msgboard_contentPage`
  - D11 posting warning: `Anyone can post through your node. Posts cost the sender proof of work, not you.`
  - Older gate: `Status needs a newer gate on this box`
- **Module ids:** `msgboard`, `el-bootnode`, `cl-bootnode`, `watch`, `private-send`, `checkpointz`.
- **Unit names:**
  - `jumpgate-mod-el-bootnode-<chain>.service`
  - `jumpgate-mod-cl-bootnode-<chain>.service`
  - `jumpgate-mod-watch.service`
  - `jumpgate-mod-checkpointz-<chain>.service`
- **Default ports:**
  - EL bootnode: UDP 30301.
  - CL bootnode: UDP 9200, which keeps clear of the beacon's 9000/9001.
  - Checkpointz: TCP 5555, bound to loopback.
  - The watch has no listener.
- **Docs.**
  - Every function a docs step covers gets `// docs:covers <step-id>` in the task that writes it.
  - Steps go in `docs/steps/modules/<id>.md`, and pathways go in `docs/pathways/<id>.yaml` (docs-system spec §1).
  - If the docs loader (`docs/docs.go`, docs plan Task 4) is not on `main` yet, write the step files and markers anyway. Leave `verified` empty, and fill it once docs plan Task 7 lands.
- **Landing page.** Each module's last step changes its label from "Planned" to "New" in `scripts/modules.json` on the `redesign-a2` branch.
  - Find that branch with `git branch -a --list '*redesign-a2*'`. If it is not in this repo, it is in the landing repo.
  - Commit on that branch only. Do not push.
- **Git.**
  - Commit on the working branch only.
  - Dev and CI live on git.craftsmanfounder.com. Never use gitlab.com.
  - Never push to GitHub without the user's OK.
- **API errors.** Every new API error code goes into `internal/api/errors.go`'s `registry` with a hint. `TestNoLiteralErrorCodes` enforces this. The new code is `module_not_applicable`.
- **Linux-only tests** run with `scripts/test-linux.sh <pkgs> -run <regex>`.

## Review Focus

1. **A box upgraded to this jumpgate, with no module on.** Expect zero unit, gateway-config or Caddyfile changes, so the wire step restarts nothing. Tests:
   - Task 3 `TestUnitsByteIdenticalWithoutModules`;
   - Task 5 `TestGatewayConfigByteIdenticalWithoutModules`.
2. **A module toggled on a box whose node is mid-sync or whose binary predates the module.** Expect:
   - "Waiting for sync", or the rebuild message;
   - never a unit that the binary rejects, so no crash loop.
   Tests: Task 6 `TestInstallVerifyFailsWithoutHelpFlag` and `TestRebuildStillMissingNeverWritesUnit`.
3. **A relay key with an empty allow list sending a module write, or a batch with one hidden write.** Expect the whole request refused with the D7 copy. Test: Task 5 `TestRelayBatchWithOneUngrantedWriteRefused`.
4. **Two box modules on one box wanting the same port.** Examples: a CL bootnode and a beacon both on 9000, or two Checkpointz on 5555. Expect a 400 naming both before anything runs. Test: Task 4 `TestValidateBoxModulesRefusesPortClash`.
5. **Private send's upstreams all failing.** Expect `eth_sendRawTransaction` to return an error and **never** fall over to a public upstream. Reads on chain 1 still work. Test: Task 17 `TestPrivateSendNeverFallsBackToPublic`.

### Task 16: Alert delivery, UI, docs, e2e, landing  [M]

**How alerts are delivered.** The watch adds no new channel unless the operator gives a webhook. It uses what exists today:

1. **The box's state file.** The watch writes `state.json`.
2. **The gate.** `modules.read` (Task 7) returns that file. For an SSH-only target, the server reads it over SSH.
3. **The controller's fleet poller.** It already polls every box. It now also reads `ModuleStatus.Alerts`, and the box's fleet row carries `alerts` and the worst alert.
4. **Where alerts show.**
   - The fleet table and the TUI fleet view show a count and the first message.
   - The tray status dot goes amber. This uses `healthWarn`, which `trayhealth.go` reserves for exactly this and does not emit yet.
   - The tooltip shows `Jumpgate — 2 alerts on box-1`.
5. **When the controller is off.** The box keeps watching and keeps the history (`Recent`). If `BoxModule.Webhook` is set, the watch also POSTs each open and clear as JSON `{"box","key","message","since","cleared"}`. An ntfy topic URL works as given.

## Out of scope / later

- **Explorer (decision pending).** It is not part of this release, and nothing in Phase 0 depends on it. The leading candidate is **Explore (valve-tech/explore, explore.valve.city) self-hosted, plus TrueBlocks** (chifra and the Unchained Index), optionally posting a manifest on chain as valve's indexer does. It will be planned separately once `.claude/research/explorer-trueblocks.md` is done. The other options and their tradeoffs:
  - **(a) Otterscan over `ots_`.**
    - It would be off by default, because it needs `ots` in `--http.api`.
    - It needs an archive node for address history; on a pruned node, search degrades to a slow linear walk.
    - It is a browser SPA that must reach the node's RPC through the gateway, so the relay needs owner-only key rules for `ots_`.
    - It is nearly frozen upstream (v2.11.0, 2025-11).
    - It is reth-only: the valve fork implements both search methods.
  - **(b) A lightweight explorer using only standard `eth_` methods.** It works on pruned nodes and on any client. It has no address history without an index.
  - **(c) A jumpgate-built minimal block, transaction and address view in the existing web UI.** It needs no new software and fits the app's design. It means a new UI surface for us to maintain, and address history again needs an index.
- **Txpool relay or probe.** It has to be built: a Rust binary on reth crates, needing `ReleaseURL` packaging. It comes next after this release, starting observe-only on 943 (`txpool-modules.md`).
- **mev-boost.** It waits on the validator spec (Spec 2). The PulseChain relay (Atlas) is down.
- **Helios.** Ethereum and Hoodi only. On PulseChain it would mean forking and patching Helios.
- **era/era1 seeder.** It is cheap to build, but demand is thin, and PulseChain clients have not been shown to consume era1.
- **PulseChain builder.** We are not shipping one. PBS on PulseChain is about 6.7% of blocks, at cents per block. rbuilder pins reth v2.2 while the fork is v2.7, and it reads reth's MDBX directly, so the two must match. *Prototype note:* at most, run a time-boxed 943 prototype, and only once the txpool or private-send work brings exclusive order flow. Atlas has no testnet relay, so the prototype needs no Atlas (`pulsechain-builder.md` §5).
- **Skipped: Portal Network** (trin is unmaintained) and **the blob archiver** (upstream was archived on 2026-10-07, and PulseChain has no blobs).
- **Per-key private-send policy** (`public`, `private` or `private-then-public`) and builder refunds. These need a new key column in the billing key store, so they come later.
- From the spec's own Out of scope:
  - `--msgboard.*` tunables;
  - a node WebSocket listener;
  - `msg/1` peer counts;
  - erigon-pulse's msgboard.
